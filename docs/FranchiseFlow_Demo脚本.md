# FranchiseFlow 演示录屏脚本（严格 3 分钟内）

> **黑客松录屏要求**：Banana Hacks 要求在 Devpost 提交**严格不超过 3 分钟（180 秒）**的公开视频（YouTube/Bilibili）。本脚本紧扣实测工程事实，先呈现最终成片对比，再深入解释多模态视觉定位初筛与本地几何跟踪技术链条。

---

## 视频信息速查

- **项目名称**：FranchiseFlow
- **核心定位**：实体加盟品牌视频本地化生成器（实拍移动视频 + 三分支招牌素材 → 三路同步成片）
- **视频总时长**：2 分 45 秒（留出 15 秒安全冗余，严控在 3 分钟内）
- **录制准备**：
  1. 启动本地服务：`python prototype/franchiseflow/app.py`，浏览器打开 `http://127.0.0.1:5000/`
  2. 演示素材：
     - 原视频：`spikes/franchiseflow/fixtures/demo_cut.mp4`（144 帧，6.0 秒）
     - 三分支招牌：`spikes/franchiseflow/assets/riverside.png`、`downtown.png`、`northpark.png`
  3. 演示模式：
     - 可直接点击界面的 **“载入默认样例素材”** 瞬间载入已完成转码的 144 帧真实渲染结果（预渲染离线回放，无录制卡顿），并说明实际端到端处理耗时约 122 秒（跟踪约 63 秒 + FFmpeg H.264 faststart 压缩转码）。

## 分段台词与画面脚本（共 5 段，严格计时）

### 0:00 – 0:40 | 成果直击：原片 vs 三路分店 H.264 浏览器播放成片

- **画面**：
  1. 浏览器打开 `http://127.0.0.1:5000/`，点击“载入默认样例素材”。
  2. 页面下方三路视频卡片立即同步循环播放 `branch_1`（滨河路店）、`branch_2`（市中心店）、`branch_3`（北园店）。
  3. 鼠标拖动其中一个视频的进度条，展示 H.264 `yuv420p` + `faststart` 编码带来的流畅拖拽与实时响应。
- **解说旁白**：
  > “实体连锁品牌在本地化推广中面临一个痛点：总店有一段高质量实拍移动运镜视频，但分发给各加盟店时，需要逐个替换门头招牌。
  >
  > 这就是 FranchiseFlow 交付的成果：左侧是一段 6 秒的真实门店运镜视频；右侧是系统全自动并行生成的 3 路分店成片。无论运镜平移、透视旋转还是焦段推近，三家分店的新招牌素材都紧密贴合在原门头表面，并已完成 H.264 与 faststart 转码，在浏览器中即点即播、支持任意进度拖动。”

---

### 0:40 – 1:20 | 核心环节：AI 视觉初筛与人机协同校准（Human-in-the-Loop）

- **画面**：
  1. 切换回界面上半部分，展示“初始化模式”切换：
     - `Gemini-3.1 视觉定位 (初筛测试)`
     - `人工校准基线 (Manual Calibration)`
  2. 点击展示首帧画布上的定位对比图（可调出 `quad_auto_preview.jpg` 与人工四角 `quad.json` 对比）。
- **解说旁白**：
  > “系统如何找到招牌？许多人认为把视频逐帧丢给多模态大模型就行，但实际上这会导致巨大的 API 费用和每帧坐标漂移闪烁。
  >
  > FranchiseFlow 采用首帧定位架构。我们授权接入了 gemini-3.1-flash-image 模型，对首帧进行视觉识别。但实测表明：当前顶尖多模态大模型在倾斜立面与复杂 3D 透视下，容易误框砖墙和门窗。
  >
  > 秉持工程严谨性，我们不宣称全自动神话，而是采用‘AI 视觉初筛 + 人工基线校准’的工作流：模型给出初始候选面，人工可在几秒内确认四角基线，保障商业落地绝对可用。”

---

### 1:20 – 2:00 | 核心工程：单次定位 + 本地几何光流跟踪（Local CV）

- **画面**：
  1. 切换到指标面板，展示：
     - 处理总帧数：`144 帧 (24 fps)`
     - 中位 SIFT 内点数：`113 个`
     - 匹配点拟合残差：`0.36 px`
     - 失败帧数：`0`
  2. 调出 `spikes/franchiseflow/outputs_demo_h264/` 抽查的首帧（000）、中间帧（072）和末帧（143），展示特征跟随轨迹。
- **解说旁白**：
  > “确定首帧招牌几何四角后，后续 143 帧全部由本地 OpenCV 几何管线驱动。
  >
  > 我们在招牌纹理区域提取 SIFT 锚点，每帧使用 RANSAC 鲁棒求解 3×3 单应透视矩阵，并辅以 Lucas-Kanade 双向光流作为极端退化兜底。
  >
  > 在整段 144 帧真实测试中，SIFT 匹配一致性内点中位数达 113 个，单应性特征拟合中位残差仅 0.36 像素。三路视频共享同一套严密几何变换，单次计算，三路并行渲染。”

### 2:00 – 2:35 | 真实指标、耗时披露与工程边界说明

- **画面**：
  1. 停留在指标仪表盘与最后一段成片。
  2. 强调指标的严谨定义与系统边界。
- **解说旁白**：
  > “在指标上我们做严谨披露：界面显示的 0.36 像素是特征匹配点的重投影拟合残差，而非物理边界绝对误差。
  >
  > 性能方面，在 720p 视频上，144 帧纯跟踪耗时约 63 秒，加上 3 路视频完整 H.264 压制与 faststart 优化，端到端耗时 122 秒。
  >
  > 边界方面：当前系统在特征丢失时会自动保留原画防穿模，但暂未包含前景人物分割遮挡（如 SAM）也不保留原片音频，这是下一阶段的演进方向。”

## 现场录制操作指南（速查）

1. **服务启动**：
   ```bash
   python prototype/franchiseflow/app.py
   ```
2. **浏览器访问**：
   打开 Chrome / Edge 访问 `http://127.0.0.1:5000/`
3. **一键载入样片演示**：
   点击按钮 `载入默认样例素材`，页面将瞬间注入完整指标、绘制四角线框并加载 3 路 H.264 视频。
4. **视频交互验证**：
   点击播放，并拖动进度条展示无缝 seek。
5. **严守时限**：严格按照上述台词朗读，总时长稳定在 2 分 40 秒左右，安全不超 3 分钟。
