# FranchiseFlow 演示录屏脚本

目标时长 2 分 35 秒，最长不超过 180 秒。演示顺序是先看原片和分支成片，再看候选定位、三帧验证和本地几何跟踪。

## 录制准备

```bash
python prototype/franchiseflow/app.py
```

浏览器打开 `http://127.0.0.1:5000/`。录屏使用页面的“载入默认样例素材”按钮回放已转码的离线结果，避免录制时等待长任务。样片生成命令：

```bash
ffmpeg -y -i spikes/franchiseflow/fixtures/real_storefront.mp4 -t 6.0 -c copy spikes/franchiseflow/fixtures/demo_cut.mp4
```

录屏样例使用三张分店招牌图。产品页面本身支持 1 到 10 个分支。

## 时间线

### 0:00–0:35，先看结果

点击“载入默认样例素材”。展示原始移动门店视频和三路独立分支成片，拖动其中一路进度条。

旁白：

> “FranchiseFlow 把一条移动门店视频变成多条分店版本。每个版本只替换招牌区域，其他画面保持原片运动。输出使用 H.264、yuv420p 和 faststart，输入有音频时保留音轨。”

### 0:35–1:10，说明候选定位

滚动到定位区域，展示首帧四角和初始化来源。指出默认模型是 `gemini-3.1-flash-image`。

旁白：

> “模型只在任务开始时提出招牌平面候选。我们把首帧、中间帧和末帧一起做几何检查。真实样例中，模型有时会把砖墙、窗户或门洞混入四边形，所以候选没有通过检查时，页面会进入人工确认。人工拖动四个角点后，任务才会继续。”

### 1:10–1:55，展示本地跟踪

展示指标和调试视频，说明 SIFT、RANSAC 和 Lucas-Kanade 的关系。

旁白：

> “确认首帧平面后，后续帧不再调用视觉模型。系统用招牌内部的 SIFT 特征匹配求单应矩阵，短暂失效时使用双向光流。几何失效的帧写入失败记录，并输出原画帧，避免沿用上一帧的替换结果。”

### 1:55–2:25，讲清证据和边界

展示 `summary.json` 中的帧数、内点、残差和失败帧。

旁白：

> “0.36 像素是 SIFT 内点的单应矩阵重投影拟合残差，不是招牌物理边缘的真实定位误差。6 秒 144 帧人工基线样例曾用约 122 秒完成，纯跟踪约 63 秒。当前版本没有前景遮挡抠像，行人经过招牌时可能覆盖在替换画面下方。”

### 2:25–2:35，开源交付

展示仓库 README、测试命令和 API 路径。

旁白：

> “代码、测试、样片生成命令和任务 API 都在公开仓库中。模型定位、人工确认、本地跟踪和多分支输出都有对应记录。”

## 录制检查

- 总时长控制在 2 分 35 秒以内。
- 样片按钮可以直接载入三路 H.264 视频。
- 录制中不要把内部拟合残差说成物理测量精度。
- 页面出现人工确认时，明确显示 `reviewed_candidate` 来源。
