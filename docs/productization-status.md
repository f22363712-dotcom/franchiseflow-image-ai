# FranchiseFlow 产品化边界

## 当前可交付范围

当前版本适合单机、单租户、受控网络中的连锁品牌视频本地化生产。它可以保存品牌配置，接收一条或一批门店视频，给每个场景提出招牌平面候选，必要时让人工拖动角点确认，再用本地 OpenCV 跟踪并输出带音轨的 H.264 分支视频。

视觉模型只参与候选定位。后续帧使用 SIFT、RANSAC 和光流在本地处理，失败帧保留原画。任务、批次、幂等记录和复核状态会落盘；输出支持 Range 下载，任务还会经过 FFprobe 契约检查。

## 已验证的运行条件

- CV 测试 73 项通过，Web 与存储测试 123 项通过。
- 可选 `FRANCHISEFLOW_API_KEY` 保护 API 和输出；匿名健康探针只返回状态和版本。
- `/api/demo_results` 默认关闭，只有 `DEMO_MODE=1` 才打开。
- SQLite 存储后端已经接入应用的显式单机模式，应用默认仍使用本地 JSON，避免误切换。

## 当前不能承诺

- 没有用户登录、团队角色和租户级对象授权。
- JSON 状态和进程内 worker 只支持一个服务进程；不能直接部署多副本。
- SQLite 模式仍使用进程内 worker，暂时不能宣称跨进程任务领取、租约恢复或在线迁移。
- 复杂转场、通用前景抠像和大幅 3D 视角变化仍可能需要人工复核。

## 下一阶段放行条件

1. 在停机窗口运行 JSON 到 SQLite 的迁移，核对任务、批次、幂等键的数量、ID、状态和时间戳。
2. 接入 SQLite worker claim、lease 和版本 CAS，做双进程重复领取、崩溃恢复和重启演练。
3. 加入用户与租户授权，所有任务、品牌配置、复核操作和输出下载都按租户过滤。
4. 把上传与成片移到私有对象存储，补配额、清理、备份和审计记录后，再考虑多副本部署。

这些步骤完成前，公开部署应保持 API key、TLS、单进程和可恢复卷的限制。
